# MeshCore Repeater Info

Консольная утилита для сбора информации со всех репитеров в контакт-листе
MeshCore Companion через USB serial. Результат — Excel-совместимый CSV-отчёт,
который обновляется после каждого репитера.

## Что собирается

- ключ репитера (полный public key);
- имя репитера — `contact_name` из списка компаньона;
- дата последнего адверта (UTC);
- версия прошивки репитера;
- owner info (там часто указан контакт администратора);
- uptime в человекочитаемом виде;
- tx/rx airtime в процентах от uptime;
- время логина репитера в UTC;
- разница часов и флаг `clock_status`;
- количество соседей;
- noise floor;
- debug flags (`err_events`);
- статус опроса, число попыток, каким паролем и в какой роли удалось войти.

## Требования

- Python 3.11 и [uv](https://docs.astral.sh/uv/);
- MeshCore Companion, подключённый по USB serial;
- настройки радио на компаньоне уже выполнены.

Версия и owner info через гостевой вход доступны на simple repeater
**v1.12.0+** (`GET_OWNER_INFO`, `0x07`). На более старой прошивке версия
помечается как `старая (...)`, а имя/owner могут остаться пустыми.

## Установка и запуск

```bash
uv sync

# посмотреть serial-порты
uv run meshcore-repeater-info --list-ports

# опросить все репитеры из контакт-листа
uv run meshcore-repeater-info -p /dev/cu.usbmodem1101 -o repeaters.csv

# безопасный тест: ровно один репитер
uv run meshcore-repeater-info -p /dev/cu.usbmodem1101 \
  --only PDO-Strelna-NE --limit 1

# переопросить уже готовые строки
uv run meshcore-repeater-info -p /dev/cu.usbmodem1101 --force

# ночной цикл
uv run meshcore-repeater-info -p /dev/cu.usbmodem1101 --loop

# экспорт в XLSX
uv run meshcore-repeater-info --input repeaters.csv --export-xlsx repeaters.xlsx
```

Без `--port` утилита пытается автоматически выбрать единственный
`usbmodem`/`ttyUSB`/`ttyACM` порт. Если портов несколько — потребуется
`--port` или переменная `MESHCORE_PORT`.

## Основные флаги

| Флаг | Назначение |
|---|---|
| `-p, --port` | serial-порт компаньона |
| `-b, --baudrate` | скорость, по умолчанию 115200 |
| `-o, --output` | путь к CSV, по умолчанию `repeaters.csv` |
| `-f, --force` | переопросить всё, сбросить счётчики и `final_fail` |
| `--alive` | переопросить только «живые»: `status=ok` и `ok_old` |
| `--dead` | переопросить только «мёртвые»: всё, где нет полной инфы, включая новые контакты; сбрасывает счётчик и `final_fail` |
| `--broken` | переопросить только существующие строки с `partial`/`broken` статусами, без новых контактов; сбрасывает счётчик и `final_fail` |
| `--only` | один репитер по префиксу ключа или имени |
| `--limit N` | максимум реально опрошенных репитеров за запуск |
| `--loop` | бесконечный цикл проходов до Ctrl+C |
| `--loop-interval` | пауза между проходами, по умолчанию 60 с |
| `--input` | CSV для экспорта (по умолчанию `--output`) |
| `--export-xlsx` | экспортировать CSV в оформленный XLSX и выйти |
| `--timeout` | единый таймаут login-попытки и любого запроса, по умолчанию 15 с |
| `--min-delay`, `--max-delay` | случайная пауза между попытками, по умолчанию 2–4 с |
| `--max-login-attempts` | лимит накопленных неудачных login-попыток, по умолчанию 35 |
| `--request-attempts` | попыток на запрос после login, минимум 5 |
| `--clock-skew-threshold` | порог `suspect` для часов, по умолчанию 600 с |
| `--passwords` | список паролей через запятую; пустой первый элемент = пустой пароль |
| `--debug` | подробный лог, включая `meshcore` |

## Как работает опрос

1. Берутся контакты компаньона с `type == repeater`.
   Если `contact_name` содержит подстроку `remove` или `delete` в любом
   регистре, репитер не опрашивается, а его строка удаляется из CSV.
2. Login: 3 попытки с пустым паролем, затем по 2 попытки с `123456`,
   `guest`, `password`, `1234`, `1234567890`. Остановка на первом успехе.
   `admin` в стандартном списке больше нет; если пароль `admin` уже был
   сохранён в отчёте, он всё равно будет попробован первым.
3. Начинаем всегда с **flood**: перед первым запросом сбрасывается маршрут
   контакта в компаньоне (`CMD_RESET_PATH`).
4. Если после flood-запроса компаньон выучил маршрут (`PATH_UPDATE`) и
   следующий запрос по сохранённому path прошёл — переключаемся на path.
5. Если запрос по path не прошёл — до конца опроса этого репитера остаёмся
   на flood. Буквальный direct/zero-hop мы не навязываем: path может быть
   zero-hop только если его так построил сам компаньон.
6. После login каждый запрос (`GET_OWNER_INFO`, `STATUS`, `NEIGHBOURS`,
   admin `ver`/`get name`/`get owner.info`) делается до 5 раз. Эти попытки
   не увеличивают login-счётчик.
7. `LOGIN_FAILED` не включает flood: это нормальный ответ, маршрут работает.
   Flood включается при таймауте.
8. Если после 5 попыток данных нет — `status=partial`, в `error` перечислено,
   чего не хватило, с числом попыток. В следующем запуске такая строка
   опрашивается снова.

## Счётчик и `final_fail`

- Считаются накопленные **неудачные** login-попытки с последнего успеха или
  `--force`.
- Счётчик сохраняется в CSV после каждой попытки.
- Когда накопленных неудачных попыток становится 35, ставится
  `status=final_fail`, строка сохраняется, репитер больше не опрашивается
  (следующая, 36-я попытка не делается).
- Успешный login сбрасывает счётчик в 0.
- `--force` сбрасывает счётчик и снимает `final_fail`.

## CSV

Файл пишется в `utf-8-sig` (BOM), разделитель `;`, окончания строк `CRLF`,
поэтому открывается в Excel. В CSV дробные проценты — с запятой; в XLSX
экспорте они записываются как настоящие числовые проценты (`0.1234` с форматом
`0.00%`), поэтому запятая CSV на них не влияет.

Порядок колонок:

```
repeater_key;contact_name;last_advert_utc;firmware_version;owner_info;
uptime;tx_airtime_pct;rx_airtime_pct;login_time_utc;
clock_skew_sec;clock_status;neighbours_count;noise_floor_dbm;
debug_flags;is_admin;login_password;login_attempts_last;
login_attempts_total;status;error
```

Пояснения:

- `last_advert_utc` — дата последнего адверта в UTC, `YYYY-MM-DD HH:MM:SS`;
- `uptime` — например, `1 дн 12 ч 15 м`;
- `tx_airtime_pct` / `rx_airtime_pct` — проценты от uptime;
- `clock_skew_sec` — `время репитера − наше время`; `clock_status=suspect`,
  если модуль разницы больше 600 секунд;
- `is_admin` — `yes/no`, явный признак admin-сессии;
- `login_password` — последний реально подошедший пароль (`(empty)` для
  пустого). При входе через ACL поле сохраняет ранее известный пароль;
- `login_attempts_total` — накопленные неудачные login-попытки;
- `status` — `ok`, `ok_old`, `partial`, `login_failed`, `timeout`, `error`,
  `final_fail`, `in_progress`.

Запись выполняется после каждого репитера через временный файл, `fsync` и
`os.replace`, поэтому прерывание не портит отчёт. Строки со `status=ok` и
`ok_old` пропускаются при следующем запуске, остальные повторяются.

## Режимы перепроверки

Без флагов: новые репитеры опрашиваются, `ok`/`ok_old` пропускаются,
`partial`/`login_failed`/`timeout`/`error`/`in_progress` повторяются,
`final_fail` пропускается.

- `--alive` — опросить только строки с `status=ok` и `ok_old`
  (у которых уже есть полная информация);
- `--dead` — опросить только строки без полной информации:
  `partial`, `login_failed`, `timeout`, `error`, `final_fail`,
  `in_progress`, а также новые контакты; счётчик login и `final_fail`
  сбрасываются;
- `--broken` — то же, что `--dead`, но **только для уже существующих строк**:
  новые контакты не добавляются. Удобно, чтобы перепроверить только
  сломанные/`partial` записи;
- `--force` — опросить всё, сбросить счётчики и `final_fail`.

Флаги `--alive`, `--dead`, `--broken` и `--force` взаимоисключающие.

## Ночной режим

```bash
uv run meshcore-repeater-info -p /dev/cu.usbmodem1101 --loop
```

- каждый проход заново читает контакт-лист — новые репитеры подхватываются;
- между проходами пауза `--loop-interval` (60 с);
- Ctrl+C останавливает цикл.

В режиме `--loop` проверяется свежесть адверта: если `last_advert` контакта
новее `last_advert_utc` в отчёте **более чем на сутки**, счётчик попыток
сбрасывается, известный пароль/ACL сохраняется, репитер опрашивается снова.
Fresh-advert работает в рамках выбранного режима: `--loop --alive` не трогает
сломанные строки, `--loop --broken` не трогает `ok`.

## Резервные копии

После каждой записи отчёта:

- новая версия пишется во временный файл и проверяется;
- предыдущая валидная версия сохраняется в `repeaters.csv.bak`;
- основной файл заменяется атомарно и проверяется ещё раз;
- при ошибке восстанавливается `.bak`.

При запуске битый основной CSV автоматически восстанавливается из `.bak`.

## Экспорт в XLSX

```bash
uv run meshcore-repeater-info \
  --input repeaters.csv \
  --export-xlsx repeaters.xlsx
```

Это отдельный режим без радио. Оформление:

- заголовок — тёмный фон, белый жирный текст;
- первый столбец ключа — серый фон и жирный текст;
- `status=ok` — зелёная статусная ячейка; `partial` — жёлтая; ошибки и
  таймауты — красный фон с белым текстом;
- вся строка светло-зелёная, если `status=ok`, `error` пустой и нет ни одной
  красной ячейки; оранжевые `noise_floor_dbm == -120` / `debug_flags != 0`
  зелёной строке не мешают;
- ошибочные строки — очень светлый красный фон;
- старые даты, старая прошивка (<1.16), `clock_status != ok` и невалидное
  `contact_name` — красный текст;
- `noise_floor_dbm == -120` и `debug_flags != 0` — оранжевый текст;
- автоширина столбцов, форматы дат/процентов/чисел, автофильтр;
- заморожены заголовок и первые два столбца (`C2`);
- строки с `remove`/`delete` в `contact_name` в XLSX не попадают.

Правила имён: только ASCII-буквы, цифры, `-`, `_` и `☀`/`☀️`; город —
2–4 блока, первый блок 3 знака; область — `LO` + 3-значный код, 3–5 блоков.

## Ограничения

- Пароли хранятся в CSV **в открытом виде** — файл отчёта не стоит передавать
  туда, где это нежелательно.
- Admin специально не подбирается: если первый успешный вход дал guest,
  другие пароли не проверяются.
- На старой прошивке версия/имя могут быть недоступны через guest-вход.
- `reset_path` меняет сохранённый маршрут контакта в компаньоне на flood;
  каждый новый опрос всё равно начинается с flood.
- Для тестов используйте `--only` и `--limit 1`, чтобы не создавать лишний
  трафик в сети.

## Разработка

```bash
uv run pytest
```

Тесты покрывают форматирование CSV, login-политику, flood/path state machine,
повторы запросов, парсинг owner info и статусов, resume/force.
